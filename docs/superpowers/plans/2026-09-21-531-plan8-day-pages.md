### Task 1: Data — per-lift supporting-done + weight/reps logging

**Files:**

- Test: `src/data/repositories.test.ts` (or the existing supporting-done test file — match where Plan 7 put `supportingDoneRepo` tests)

**Interfaces:**
- Consumes: existing `db.supportingDone` (Dexie store `'++id, date'`), `LiftKey`, `AssistanceCategory`.
- Produces:
  - `interface SupportingDone { id?: number; date: string; liftKey: LiftKey; category: AssistanceCategory; name: string; weight: number | null; reps: number | null }`
  - `supportingDoneRepo.forDate(date: string): Promise<SupportingDone[]>` (unchanged signature)
  - `supportingDoneRepo.toggle(date: string, liftKey: LiftKey, category: AssistanceCategory, name: string): Promise<void>` — delete matching `(date, liftKey, category, name)` row if present, else add `{ date, liftKey, category, name, weight: null, reps: null }`.
  - `supportingDoneRepo.log(date: string, liftKey: LiftKey, category: AssistanceCategory, name: string, patch: { weight?: number | null; reps?: number | null }): Promise<void>` — upsert: update the matching row's weight/reps, or create it (marking it done) if none exists.

- [ ] **Step 1: Write failing tests** — in the supporting-done test file:
  - `toggle` adds then removes a per-lift row: `await toggle('2026-09-21','press','pull','Chin-ups')` → `forDate` has 1 matching row with `liftKey:'press'`; toggling again → 0.
  - per-lift independence: toggle `('2026-09-21','press','pull','Chin-ups')` and `('2026-09-21','bench','pull','Chin-ups')` → `forDate` returns 2 distinct rows; removing press's leaves bench's.
  - `log` upsert: `await log('2026-09-21','press','pull','Chin-ups',{weight:20,reps:12})` creates a done row with `weight:20, reps:12`; a second `log(...,{reps:10})` updates reps to 10, keeps weight 20, still one row.

**Files:**
- Create: `src/ui/components/DayStrip.tsx`
- Modify: `src/ui/screens/Home.tsx`
- Test: `src/ui/components/DayStrip.test.tsx` (new), `src/ui/screens/Home.test.tsx` (update)

**Interfaces:**
- `DayStrip({ lifts, activeDay, doneKeys, onSelect }: { lifts: { key: LiftKey; label: string }[]; activeDay: number; doneKeys: Set<LiftKey>; onSelect: (index: number) => void })` — 4 buttons (Press/Bench/Squat/Deadlift short labels), active one accent-styled with `aria-current`/`aria-pressed`, a ✓ badge when `doneKeys.has(key)`; click → `onSelect(index)`.

An `IntersectionObserver` (threshold ~0.6, root = the strip) sets `activeDay` to the centered page on swipe. `doneKeys` = lifts with a done session for the selected week (already computed in Plan 7). Everything else (week tabs, protocol line, rest timer, cycle-end routing, session pass-through) unchanged.
