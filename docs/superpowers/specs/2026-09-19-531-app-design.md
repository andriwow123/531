# 5/3/1 Training App — Design Spec

- **Date:** 2026-09-19
- **Status:** Approved (design), pending spec review
- **Author:** andriwow123 + Claude
- **Owner context:** Single user, non-developer ("vibecoding"). Claude does all engineering; explanations stay plain-language.

---

## 1. Purpose

A personal app for running Jim Wendler's **5/3/1** strength program: set up training maxes, follow the correct weights/sets/reps each workout, log what you did, capture AMRAP performance, and get guided progression at the end of each cycle. Local-first and installable, with correctness of the underlying 5/3/1 math as the top priority.

## 2. Guiding principles

1. **The main workout screen stays clean.** All configuration lives in **Settings**, never in the day-to-day UI.
2. **Configurability without clutter.** A display-mode system flexes the app from dead-simple ("what lift, how heavy, sets × reps") to deep-data, per the user's choice.
3. **Correctness first.** The 5/3/1 math lives in a pure, unit-tested core so it can't be broken by UI changes.
4. **Local-first, offline, private.** No accounts or network required to use the app. Architected so cloud sync can be added later without a rewrite.
5. **Portable.** The same codebase can later be wrapped into a native app-store app (Capacitor) with no rewrite.

## 3. Target user & scope

- Primary (and only, for v1) user: the owner. No multi-user, no accounts in v1.
- The owner trains ~4× per week; lift days are not fixed to specific weekdays.

## 4. Tech stack

| Concern | Choice | Rationale |
|---|---|---|
| Language | TypeScript | Type-safety for the training math |
| UI | React + Vite | Standard, fast dev, PWA-friendly |
| Styling | Tailwind CSS + custom theme tokens | Fast styling; custom orange/black theme avoids a templated look |
| Data | IndexedDB via **Dexie** | Robust local storage for history & charts; behind a repository interface so a sync adapter can be added later |
| Charts | Recharts | Simple, readable line charts |
| PWA | vite-plugin-pwa | Installable, offline, app manifest |
| Routing | React Router | A handful of screens |
| Exercise data | `free-exercise-db` (yuhonas, MIT) | Open-source exercise library with images |
| Tests | Vitest | Unit tests for the domain core (TDD) |
| Future packaging | Capacitor (not in v1) | Same code → iOS/Android app later |

**Rejected:** vanilla single-file JS (scope too large to maintain, awkward to port); Next.js (SSR fights offline/local-first).

## 5. Architecture — four layers

1. **Domain core** (`src/domain/`) — pure TypeScript, no UI, no storage. All 5/3/1 rules and math. Fully unit-tested (TDD). Correctness lives here.
2. **Data layer** (`src/data/`) — Dexie tables + repositories behind interfaces. A future `SyncAdapter` (Supabase) implements the same interfaces without touching screens.
3. **Settings engine** (`src/settings/`) — typed settings schema, presets, granular overrides, and a resolver that produces "what shows on the main screen."
4. **UI** (`src/ui/`) — React screens/components consuming the above.

Each unit answers: what it does, how it's used, what it depends on. Domain core depends on nothing; data depends on domain types; UI depends on data + settings.

## 6. Data model (Dexie tables)

- **settings** (singleton): `units ('kg'|'lb')`, `roundingIncrement`, `tmPercent` (default 0.85), `theme {mode, accent}`, `displayPreset ('simple'|'standard'|'detailed')`, `displayOverrides {elementKey: bool}`, `restTimer {enabled, defaultSeconds, notify}`, `schedule {mode: 'rolling'|'fixedDays', days?}`, `template {selected: 'base'|'bbb'|'fsl', fivesPro: bool, warmups: bool, supplemental params}`, `progression {increments {upperKg, lowerKg}, rpeThresholds}`, `exerciseDemos: bool`.
- **lifts** (the 4 mains): `key ('press'|'bench'|'squat'|'deadlift')`, `name`, `category ('upper'|'lower')`, `oneRM`, `trainingMax`, `progressionIncrement`, `demoRef`.
- **cycles**: `index`, `startedAt`, `status ('active'|'completed')`, `templateSnapshot`, `tmSnapshot {liftKey: number}`.
- **sessions** (workouts): `cycleId`, `week (1–4)`, `liftKey`, `date`, `status`, `plannedSets[]`, `loggedSets[] {targetReps, weight, actualReps, done, isAmrap}`, `amrapReps`, `estimated1RM`, `rpe`, `notes`.
- **assistance**: `sessionId?`, `category ('push'|'pull'|'core'|'singleLeg')`, `name`, `sets`, `reps`, `load/notes`.
- **bodyweight**: `date`, `weight`.
- **progressionEvents**: `cycleId`, `liftKey`, `rpe`, `amrapReps`, `suggestion ('bump'|'hold'|'reset')`, `suggestedTm`, `acceptedTm`.

## 7. The 5/3/1 domain rules (the math)

### 7.1 Lifts
Four mains, fixed: Overhead Press, Bench Press, Squat, Deadlift. Upper = press, bench (+2.5 kg / +5 lb default). Lower = squat, deadlift (+5 kg / +10 lb default).

### 7.2 Training Max
`TM = round(oneRM × tmPercent, increment)`. `tmPercent` default **0.85**, configurable in Settings.

### 7.3 Units & rounding
`units` = kg (default) or lb. `roundingIncrement` configurable (default 2.5 kg / 5 lb). `roundToIncrement(value, increment)` rounds to nearest.

### 7.4 Week / set schemes (percent of TM)

| Week | Set 1 | Set 2 | Set 3 (top) |
|---|---|---|---|
| 1 — 5s | 65% × 5 | 75% × 5 | 85% × 5+ |
| 2 — 3s | 70% × 3 | 80% × 3 | 90% × 3+ |
| 3 — 5/3/1 | 75% × 5 | 85% × 3 | 95% × 1+ |
| 4 — Deload | 40% × 5 | 50% × 5 | 60% × 5 |

"+" = AMRAP (as many reps as possible). Deload has no AMRAP.

### 7.5 Templates (all selectable in Settings)
- **Base 5/3/1:** the three main sets above.
- **5s PRO (modifier):** weeks 1–3 main sets all done as **5 reps, no AMRAP** (same percentages). Deload unchanged. Pairs with BBB/FSL.
- **Boring But Big (BBB):** after main work, **5 × 10** supplemental at a configurable % of TM (default 50%, range 30–60%), same lift by default (opposite-lift option configurable).
- **First Set Last (FSL):** after main work, sets at the week's **first working percentage** (65/70/75%); default **5 × 5** FSL, sets/reps configurable.
- **Warm-ups (toggle, default on):** 40% × 5, 50% × 5, 60% × 3.

### 7.6 AMRAP → estimated 1RM
Epley: `estimated1RM = weight × (1 + reps / 30)`. Logged per AMRAP set; new PRs highlighted in history.

### 7.7 Progression suggestion (end of cycle, RPE-informed)
Evaluated per lift at cycle end using the week-3 top set (1+) plus reported RPE (captured in 0.5 steps: … 8.5, 9, 9.5, 10). Defaults (all configurable later):
- **Bump** (progress TM by the lift's increment): top set completed AND RPE ≤ 9.
- **Hold** (repeat same TM next cycle): top set completed but RPE ≥ 9.5.
- **Reset** (drop TM ~10%: `newTm = round(currentTm × 0.9)`): failed to hit the prescribed top-set reps.
Always presented as a **suggestion** the user accepts or overrides; the chosen value is recorded in `progressionEvents` and applied to the next cycle.

### 7.8 Deload
Week 4 uses the deload scheme; no AMRAP, no progression change. Skippable per Settings.

### 7.9 Custom percentages / templates
Settings includes an advanced editor to adjust the main week percentages and define a custom supplemental block. Ships with sensible validation; advanced users only.

### 7.10 Plate calculator
`computePlates(target, barWeight, availablePlates, unit)` → plates per side. Bar weight and available plate inventory configurable in Settings.

## 8. Settings engine & display resolver

- **Presets:** `simple` (sets + weights + rep logging only), `standard` (adds plate breakdown, rest timer, est-1RM, notes), `detailed` (everything, incl. charts, assistance, bodyweight widgets).
- **Granular overrides:** per-element on/off that override the preset. Elements: `plateBreakdown`, `restTimer`, `notes`, `estimated1RM`, `warmups`, `charts`, `amrapPrBadges`, `assistanceSection`, `bodyweightWidget`.
- **Resolver:** `resolveDisplay(preset, overrides) → { [elementKey]: boolean }`, consumed by the Home screen so config never leaks into the workout UI.

## 9. Screens & flows

1. **Onboarding (first run):** choose units → enter estimated 1RM per lift → confirm derived TM (shows the 0.85) → pick template + schedule (or accept defaults) → finish. Every step defaultable/skippable.
2. **Home / Today:** next scheduled lift, week label, working sets with exact rounded weights, plate breakdown, big rep-logging controls, AMRAP capture on the top set, rest timer, notes, est-1RM — each shown only if the display resolver enables it.
3. **Cycle view:** current 4-week block and progress.
4. **History / Progress:** per-lift weight & est-1RM charts, cycle-by-cycle log, AMRAP PR highlights.
5. **End-of-cycle flow:** per lift, prompt RPE + read AMRAP → show suggestion (bump/hold/reset) → user confirms → generate next cycle.
6. **Settings:** units & rounding · TM % · templates & supplemental · schedule (rolling vs fixed weekdays) · display mode (preset + toggles) · rest timer · theme (orange/black, dark mode) · backup/export/import · exercise demos · advanced (custom percentages) · plate inventory · bodyweight.
7. **Exercise demo:** expandable per-lift card with image + instructions from `free-exercise-db`.

## 10. Features (Part F — all in v1 unless noted)

Plate calculator · rest timer + notification · dark mode · deload handling · assistance-work tracker (push/pull/core/single-leg) · bodyweight tracking · JSON backup/export & import · exercise demos · custom-percentages/templates editor · orange/black theme + display-mode engine.

## 11. Aesthetic / design direction

- **Vibe:** looks like a well-made app from ~2020 — flat cards, moderate rounding (8–12px), subtle borders, minimal gradients, clear hierarchy. **Not** the default Claude/generic look, not glassy/neumorphic, not sterile 2024-minimal.
- **Color:** orange accent on near-black (dark-first), warm off-white text. Light mode available.
- **Numbers:** weights are the hero — large, high-contrast, tabular figures, readable at a glance mid-set.
- Exact palette and type to be finalized with mockups during the frontend-design step (visual options presented for the owner to pick).

## 12. Testing strategy

- **TDD on the domain core:** TM computation, rounding edge cases, per-template/week set generation (Base, 5s PRO, BBB, FSL, warm-ups, deload), Epley estimate, plate calculation, progression-suggestion logic.
- Lighter integration tests on data repositories and key flows.

## 13. Phasing

- **v1 (this build):** everything in §§7–11 — full local-first app with all Part F features except the two below.
- **Fast-follow (phase 1.5):** 7th-week TM test/PR week and Leader/Anchor (5/3/1 Forever) blocks. The cycle engine is designed to accept these (cycles can be grouped into blocks; special weeks are a week-type variant) so adding them does not require reworking the core.
- **Phase 2:** Supabase auth + cross-device cloud sync via the data-layer `SyncAdapter` interface.

## 14. Non-goals (v1)

Cloud sync / accounts · multi-user · native app-store packaging (architected for, not shipped) · 7th-week & Leader/Anchor (fast-follow).

## 15. Assumptions

- Single user, one device (with JSON backup for safety/transfer).
- `free-exercise-db` subset bundled locally (offline-capable); demos optional per Settings.
- PWA runs offline after first load.
